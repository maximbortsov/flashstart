# Граничные случаи и события аналитики

## Граничные случаи: где ломается критерий успеха

Пройди по списку и возьми только те случаи, которые реально бьют по SC этого продукта.

| Группа | Что спросить | Пример поведения |
|---|---|---|
| **Пусто** | Что видит клиент, когда данных ещё нет? | Первый экран объясняет, что здесь появится, и ведёт к первому действию |
| **Много** | Что будет при 100× обычного объёма? Длинные имена, сотни записей | Список с поиском; длинный текст обрезается без поломки вёрстки |
| **Повтор** | Клиент нажал дважды, отправил форму повторно, вернулся назад | Второе действие не создаёт дубль |
| **Обрыв** | Клиент ушёл на середине и вернулся через день | Начатое сохранено, продолжает с того же шага |
| **Ошибка ввода** | Неверный формат, пустое обязательное поле | Сообщение называет, что не так и как исправить |
| **Сбой снаружи** | Нет сети, упал внешний сервис, платёж не прошёл | Понятное сообщение, ничего не потеряно, можно повторить |
| **Чужие права** | Человек видит или меняет то, что ему не принадлежит | Доступ закрыт; ссылки не раскрывают чужие данные |
| **Время** | Часовые пояса, полночь, просроченные сроки | Время показывается в поясе клиента |
| **Деньги** | Возврат, частичная оплата, двойное списание | Каждое списание видно и сверяется |
| **Язык и рынок** | Другая валюта, формат даты, длина слов в переводе | Форматы рынка из frame |
| **Устройство** | Маленький экран, медленная связь | Главное действие доступно на телефоне |

## События аналитики

### Какие события нужны

1. **Измерители SC.** Для каждого SC, на который ссылается FR, — хотя бы одно событие, из которого считается метрика SC. Если метрика — время между действиями, нужны оба события.
2. **Шаги до Aha.** По событию на каждый шаг флоу от входа до Aha — чтобы видеть, на каком шаге уходят.
3. **Aha.** Отдельное событие в момент Aha Moment: самое важное в продукте.
4. **Источник.** Откуда пришёл клиент — свойство первого события, а не отдельное событие.

Обычно хватает 4–10 событий. Не отправляй «всё подряд»: каждое лишнее событие — шум в отчёте.

### Как называть

- `объект_действие` в прошедшем времени, латиницей, snake_case: `booking_created`, `reminder_sent`, `slot_filled`.
- Одно имя — одно значение во всём продукте. Не путать `signup_completed` и `account_created`.
- Свойства — тоже snake_case: `source`, `slot_id`, `minutes_to_fill`.
- Персональные данные (имя, телефон, email) в события не кладём.

### Таблица в спецификации

| ID | Событие | Когда отправляется | Свойства | Измеряет |
|---|---|---|---|---|
| EV1 | `slot_filled` | свободное окно занято новым клиентом | `slot_id`, `minutes_to_fill` | SC1.1 |

### Kill / continue

Для каждого главного SC: метрика из событий, порог, срок после релиза, решение.

> «Через 14 дней после запуска у ≥ 3 из 5 мастеров медиана `minutes_to_fill` ≤ 30 → продолжаем. Иначе — возвращаемся к A2 (механика) в `fs-learn`.»
