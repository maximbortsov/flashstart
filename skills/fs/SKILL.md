# fs — где мы и что дальше

Задача: за 10 секунд показать состояние и назвать **один** следующий шаг. Роутер ничего не пишет в артефакты, кроме полей `next` и `validation_debt` в `.fs/state.yaml`.

## Команды

| Запрос | Что делаем |
|---|---|
| `fs` / «статус» / «что дальше» | статус текущей гипотезы и следующий шаг |
| `fs list` / «покажи гипотезы» | таблица всех `docs/fs/h-*` |
| `fs switch h-002` | переключить текущую гипотезу в `.fs/state.yaml` |
| `fs help` / «как это устроено» | короткое объяснение FlashStart |

## Статус

1. Найди `.fs/state.yaml` в корне продуктового репо.
   - **Нет** → гипотез ещё нет. Коротко объясни, что такое FlashStart (см. «Как устроено»), и предложи `fs-frame`.
2. Запусти `python3 scripts/trace-check.py docs/fs/<hypothesis> --json`. Если в проекте нет `scripts/trace-check.py` (FlashStart поставлен глобально) — возьми `~/.claude/skills/fs/trace-check.py`; во всех остальных скиллах FlashStart путь к скрипту тот же. Нет Python или скрипта — посчитай вручную по артефактам: открытые допущения в `02-rat.md` и `skipped_gates`.
3. Выведи блок:

```
h-001 «<название из 01-frame.md>» · трек M · шаг: build
Путь: frame ✓ → rat ✓ → spec ✓ → build ◐ (S1.2 из 4) → ship → learn
Долг непроверенного: 3 (допущений 1, пропущенных шагов 1, spec на Job из головы 1)
Трассировка: зелёная | ошибок N, предупреждений M — главная: <одна строка>
Пропущенные гейты: fs-rat — «код вместо теста без кода» (2026-10-14)
Дальше: fs-build S1.2
```

4. Обнови в `.fs/state.yaml` поля `validation_debt` (из `trace-check`) и `next`.

Если трассировка красная — следующим шагом назови исправление (какой файл и что), а не движение дальше. Если пользователь всё равно хочет дальше — это его решение; предупреди одной строкой.

## Как выбрать следующий шаг

Иди по таблице сверху вниз; первая подходящая строка — ответ.

| Условие | Следующий шаг |
|---|---|
| Нет `01-frame.md` | `fs-frame` |
| Нет `02-rat.md` | `fs-rat` |
| Трек S, нет `03-test.md` | `fs-test` |
| Трек S, тест идёт, дата решения не наступила | ждать до <даты>; напомнить заполнять журнал |
| Трек S, дата решения наступила, нет `06-learn.md` | `fs-learn` |
| Трек M или L, нет `04-spec.md` | `fs-spec` |
| Трек L, нет `05-architecture.md` | `fs-plan` |
| Есть история в статусе `in-progress` | `fs-build <она>` |
| Есть история в статусе `todo` / `planned`, а эпик E1 ещё не готов | `fs-build <первая по порядку>` |
| Все истории E1 в `review` / `done`, нет `07-ship.md` | `fs-ship` (показать путь до Aha людям как можно раньше) |
| Есть ещё истории в `todo` | `fs-build <первая по порядку>` |
| Есть `07-ship.md`, дата Kill / continue не наступила | ждать до <даты>; смотреть, что события приходят |
| Дата Kill / continue наступила, нет `06-learn.md` | `fs-learn` |
| Есть `06-learn.md` | по его `decision`: continue → следующий шаг трека; pivot → `fs-rat` новой гипотезы; kill → `fs-frame` для новой идеи |

Истории в статусе `review` не блокируют следующий шаг, но напомни: пользователь должен посмотреть их и перевести в `done`.

## Список гипотез

Таблица по всем `docs/fs/h-*`:

| Гипотеза | Название | Трек | Шаг | Решение | Долг |
|---|---|---|---|---|---|

Текущая — отмечена. Решение — из `06-learn.md`, если есть.

## Переключение

`fs switch h-NNN` — проверь, что папка есть; обнови в `.fs/state.yaml` поля `hypothesis`, `track` (из `02-rat.md`), `stage` (по последнему артефакту), `next` (по таблице выше), `validation_debt`. `skipped_gates` относятся к гипотезе: при переключении сохрани старые в `06-learn.md` или в комментарии и начни список заново — пропуски одной гипотезы не должны висеть на другой.

## Как устроено (для `fs help` и первого запуска)

Не больше 10 строк:
- FlashStart проводит идею от Job клиента до работающего интерфейса и старается **убить слабую идею как можно раньше и дешевле**.
- Каждый шаг оставляет файл в `docs/fs/h-NNN/`, всё связано номерами: Job → критерии успеха → допущения → требования → истории → события.
- Три трека: **S** — проверка без кода; **M** — небольшой прототип; **L** — полноценная разработка. Трек выбирает `fs-rat`.
- Шаги: `fs-frame` → `fs-rat` → (`fs-test` | `fs-spec` → `fs-plan` → `fs-build` + `fs-design` → `fs-ship`) → `fs-learn`.
- Проверки на выходе шагов предупреждают, но не запрещают. Каждый пропуск увеличивает долг непроверенного — его видно здесь.
- Начать: `fs-frame` и описание идеи своими словами.

## Чего не делать

- Не запускать следующий скилл самому — только назвать его. Пользователь решает, когда идти.
- Не исправлять артефакты молча: роутер показывает, что не так, исправляет соответствующий скилл.
- Не выдавать длинный отчёт: статус — это 6–8 строк.
