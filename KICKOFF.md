# FlashStart — стартовое задание для Claude Code

Положи этот файл и `FRAMEWORK.md` в корень нового репо `flashstart/`, затем дай Claude Code промпт из раздела 3.

## 1. Правила работы с источниками (важно для публичного продукта)

- Исходники клонируются в `_sources/`, папка **сразу в `.gitignore`**. В репо FlashStart они не попадают.
- Из источников берём идеи и структуру. Тексты, шаблоны, правила, примеры пишем заново. Запрещено копировать абзацы, таблицы, промпты и списки, даже с перефразированием близко к оригиналу.
- Фиксируем версии: для каждого источника записать commit hash в `_sources/VERSIONS.md` (BMAD V7 сейчас в активной разработке, без фиксации анализ «поплывёт»).
- Лицензии каждого источника записать в `docs/inspiration.md` (для README).

## 2. Порядок этапов

1. **Скелет репо** по §7 FRAMEWORK.md, `CLAUDE.md` с правилами (пути, ID-схема, гейты-предупреждения, язык артефактов = язык пользователя, правило оригинальности).
2. **Анализ источников** → `docs/analysis/{nmt,bmad,impeccable}.md`: что делает каждая часть, что берём / режем (сверка с §2 FRAMEWORK.md), какие идеи переписываем. Только конспект своими словами.
3. **Контракт артефактов**: шаблоны с frontmatter и ID, `scripts/trace-check.py` по правилам §5 + тесты на нём.
4. **Скиллы по порядку пайплайна**: `fs-frame` → `fs-rat` → `fs-test` → `fs-spec` → `fs-plan` → `fs-build` → `fs-design` → `fs-ship` → `fs-learn` → роутер `fs`. Каждый SKILL.md ≤ ~300 строк.
5. **Синтетический пример `examples/h-001`**: прогон по треку M, на нём определяется пресет «starter». `trace-check` должен быть зелёным.
6. **Проверка оригинальности**: сравнить тексты FlashStart с `_sources/` на дословные совпадения (n-граммы ≥ 8 слов), отчёт в `docs/analysis/originality.md`.

После каждого этапа — коммит и короткий отчёт: что сделано, какие решения приняты, что спорно.
