# FlashStart — правила для Claude Code

Этот репозиторий — исходники фреймворка FlashStart (набор скиллов `fs-*`). Спецификация — `FRAMEWORK.md`, план работ — `KICKOFF.md`. При противоречии между этим файлом и `FRAMEWORK.md` прав `FRAMEWORK.md`; противоречие выносится автору списком, а не правится молча.

## 1. Оригинальность (жёсткое правило)

- `_sources/` — только для чтения и анализа. Папка в `.gitignore`, в коммиты не попадает.
- Из источников берём идеи и структуру. Тексты, шаблоны, правила, примеры, промпты и списки пишем заново. Не копировать абзацы и таблицы, не пересказывать близко к оригиналу, не переносить порядок и формулировки пунктов из чужих списков.
- В теле скиллов нет ссылок на чужие методики и их фирменных терминов. Источники вдохновения упоминаются только в `README.md` и `docs/inspiration.md`.
- Общие термины (Job, критерий успеха, Aha Moment, допущение, гипотеза) использовать можно. Чужие торговые марки в названиях скиллов, файлов и артефактов — нельзя.
- Перед релизом: проверка n-граммами ≥ 8 слов против `_sources/` (этап 6, `docs/analysis/originality.md`).

## 2. Язык

- Артефакты пользователя пишутся на языке пользователя.
- Исходники фреймворка (SKILL.md, шаблоны, METHOD.md) — на русском; ID, ключи frontmatter, имена файлов и путей — латиница.

## 3. Пути

| Что | Где |
|---|---|
| Скиллы | `skills/<имя>/SKILL.md` (≤ ~300 строк), длинное — в `skills/<имя>/references/` |
| Шаблоны артефактов | рядом со скиллом: `template.md`, `*.template.md` |
| Проверка трассировки | `scripts/trace-check.py`, тесты — `tests/` |
| Эталонный прогон | `examples/h-001/` |
| Анализ источников | `docs/analysis/` |
| Артефакты пользователя (в его продуктовом репо) | `docs/fs/h-NNN/01-frame.md … 07-ship.md`, `stories/*.md` |
| Состояние | `.fs/state.yaml` в продуктовом репо |

Нумерация артефактов фиксированная: `01-frame`, `02-rat`, `03-test`, `04-spec`, `05-architecture`, `06-learn`, `07-ship`.

## 4. ID-схема

| Сущность | Формат | Рождается в |
|---|---|---|
| Гипотеза | `h-001` | `fs-frame` |
| Job | `J1` | frame |
| Критерий успеха | `SC1.1` (первая цифра — номер Job) | frame |
| Допущение | `A1` | rat |
| Функц. требование | `FR1` | spec |
| Событие аналитики | `EV1` | spec |
| Эпик / история | `E1` / `S1.2` (первая цифра — номер эпика) | plan (в треке M — spec) |

- ID не переиспользуются. Удалённая сущность помечается `status: dropped`, номер не занимается заново.
- Каждая ссылка на ID указывается в frontmatter (`refs`) — это источник правды для `trace-check`, текст тела вторичен.
- Уровень уверенности Job и SC: `[head]`, `[interview]`, `[data]` (правила — `FRAMEWORK.md` §5).

## 5. Гейты

- Гейты **предупреждают, а не блокируют**. Скилл показывает, что не выполнено и какой риск это несёт, и спрашивает, продолжать ли.
- Пропуск записывается в `.fs/state.yaml` в `skipped_gates` и увеличивает `validation_debt`.
- Перед стадией разработки всегда задаётся вопрос «можно ли проверить без кода» (`fs-rat`).

## 6. Работа в этом репо

- После каждого этапа из `KICKOFF.md` — коммит и короткий отчёт: что сделано, какие решения приняты, что спорно.
- Не начинать следующий этап без подтверждения автора, если этап этого требует.
- `FRAMEWORK.md` правит только автор; предложения — списком в отчёте.
