# Метод FlashStart

## Принципы

1. **Всё — гипотеза.** Любая работа начинается с записанного условия, при котором мы её бросаем. Слова пользователя — тоже гипотеза, а не факт.
2. **От Job, а не от фичи.** Требования выводятся из того, чего человек пытается добиться, и из того, по каким признакам он поймёт, что добился.
3. **Код — последнее средство.** Перед разработкой всегда спрашиваем: можно ли узнать то же самое без кода?
4. **Файлы и ID.** Каждый шаг оставляет файл с фиксированным путём. Каждое требование можно проследить до Job.
5. **Процесс по размеру задачи.** Маленькой проверке — короткий путь, большой системе — полный.
6. **Интерфейс проверяется списком, а не вкусом.** Дизайн опирается на контекст продукта и проходит чек-лист типовых ошибок.

## Глоссарий

| Термин | Что значит в FlashStart |
|---|---|
| **Гипотеза (`h-NNN`)** | Одна проверяемая идея продукта со своей папкой артефактов. |
| **Job (`J`)** | Изменение, которого человек хочет добиться в своей ситуации: из какого состояния, в какое, и ради чего. Формулируется глаголом от лица клиента. |
| **Core Job** | Job, который делает наш продукт. |
| **Big Job** | Job уровнем выше: ради чего клиент делает Core Job. Источник мотивации и языка для текстов. |
| **Критерий успеха (`SC`)** | Измеримый признак, по которому клиент решает, что Job сделан достаточно хорошо. Без способа измерения критерием не считается. |
| **Цепочка шагов** | Последовательность действий клиента от триггера до результата. Место, где цепочка рвётся, — главный кандидат на ценность. |
| **Aha Moment** | Первый момент, когда продукт заметно превзошёл ожидания клиента. Должен наступать как можно раньше в цепочке. |
| **Механика ценности** | Способ сделать Job дешевле по деньгам, времени, усилиям или нервам: убрать шаг, сделать за клиента, починить разрыв и т. п. |
| **Допущение (`A`)** | Утверждение, которое должно оказаться правдой, чтобы гипотеза сработала. Пишется утвердительно и так, чтобы один тест мог его опровергнуть. |
| **Kill-критерий** | Заранее записанный порог: если тест показал хуже — гипотеза закрывается или меняется. |
| **Validation debt** | Число открытых допущений, на которых сейчас стоит работа. |
| **Трек (S/M/L)** | Глубина процесса, выбранная по размеру задачи. |
| **Гейт** | Проверка на выходе шага. Предупреждает о риске, но не запрещает идти дальше. |
| **Функц. требование (`FR`)** | Что продукт должен уметь; всегда со ссылкой на `SC`. |
| **Событие (`EV`)** | Событие аналитики, которым после релиза измеряется `SC`. |
| **Эпик / история (`E`, `S`)** | Единицы разработки. История — объём одной сессии, с критериями приёмки. |
