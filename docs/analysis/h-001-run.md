## Пресет starter — предложение

**Проверенный кандидат: Node.js 22 без внешних зависимостей.**
`node:http` — сервер, `node:sqlite` — база, `node:test` — тесты, TypeScript через `--experimental-strip-types` без сборки, HTML на сервере, JavaScript только для мелочей.

| Критерий из `stack-presets.md` | Как показал себя |
|---|---|
| Один язык | да |
| Одна команда запуска и тестов | да: `npm start`, `npm test` |
| База без администрирования | да, файл SQLite — но см. риск 2 |
| Вход без своих паролей | секретная ссылка мастера — для прототипа хватило |
| Деплой по `git push` | не проверено (сухой прогон) |
| Тесты из коробки | да, встроенный тест-раннер |
| Агент знает стек | да; ошибок агента из-за стека не было |

Плюсы: ничего не нужно устанавливать, работает без сети, нечему ломаться при обновлении зависимостей, детектор дизайна легко проверяет HTML с сервера.

Риски:
1. `node:sqlite` и запуск TypeScript без сборки в Node 22 помечены как экспериментальные (выводится предупреждение; скрыто флагом). Хостинг должен поддерживать Node ≥ 22.6.
2. SQLite требует **постоянного диска** у хостинга. На платформах с одноразовым диском нужна управляемая база — это уже другой стек.
3. Маршрутизация вручную нормальна для 5–10 страниц; для трека L с десятками экранов нужен фреймворк.

**Предложение:** пресет starter = этот стек **для трека M** (прототип до ~10 экранов). Для трека L пресет остаётся открытым и выбирается на первой гипотезе трека L. Нужно решение автора.
